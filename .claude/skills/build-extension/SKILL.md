## Steps

1. **Confirm the edit was made in source, not output.** If the user's change
   was made under `semd-extension/chrome_extension/` or `firefox_addons/`,
   stop and explain those are generated by `scripts/build-extension.js` from
   `semd-extension/app/` — the real edit needs to happen there instead, or it
   will be silently overwritten on the next build.

2. **Build the target(s) the user asked for**, from `semd-extension/`:
   ```bash
   npm run build:chrome    # writes chrome_extension/
   npm run build:firefox   # writes firefox_addons/
   npm run build:all       # both, sequentially
   ```

3. **Verify output actually changed** — check that `chrome_extension/` and/or
   `firefox_addons/` have a newer mtime than before the build, not just that
   the npm command exited 0.

4. **Tell the user how to load/reload it**, matching what they built:
   - **Chrome:** `chrome://extensions/` → enable Developer mode → "Load
     unpacked" → select `chrome_extension/`. To reload after a rebuild, click
     the refresh icon on the extension's card.
   - **Firefox:** `about:debugging#/runtime/this-firefox` → "Load Temporary
     Add-on" → select `firefox_addons/manifest.json`. Reload via the reload
     icon next to the addon.

5. If the user wants a distributable zip rather than just a local reload-test
   build, point to the "Building for Distribution" section of
   `semd-extension/README.md` rather than improvising packaging steps.

## Notes

- `npm run clean` removes `out/`, `dist/`, `.next/`, `builds/`, `node_modules/`
  and both extension output directories — treat it as destructive and confirm
  with the user before running it, don't run it automatically as part of a
  routine build.
- `chrome_extension/` and `firefox_addons/` are tracked in this submodule's
  git history despite being build output — don't be surprised that a rebuild
  shows as a large diff; that's expected, not a sign something broke.
